# Publish 1.0.8 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish `@emamid/svelte-data-table` 1.0.8 from commit `583cb64` by creating GitHub release `v1.0.8`, so the existing workflow publishes it to npm.

**Architecture:** Do not change the package. Create one non-draft, non-prerelease GitHub release whose tag points at `583cb64e5a2e90679ea7dedadfe47d8ea99abd3e`. That `release` `created` event is what `.github/workflows/release-package.yml` already uses to run `npm publish`. Confirm the tag, the workflow, and the npm version. Stop if the workflow fails.

**Tech Stack:** GitHub Releases via `gh`, the existing `Node.js Package` workflow, public npm registry.

**Spec:** `docs/superpowers/specs/2026-11-02-publish-1.0.8-design.md`

## Global Constraints

- Release tag `v1.0.8`, target commit `583cb64e5a2e90679ea7dedadfe47d8ea99abd3e`, not a prerelease, not a draft.
- Release notes are exactly `Fixed module type`.
- Do not change files on `master` before the release. Do not commit the spec or this plan first.
- Do not publish with a local `npm publish` or an npm token.
- If the workflow fails, stop and report the failure. Do not publish a second way.
- No source, dependency, workflow, `@types/node`, or documentation changes in this release.

## Review Focus

- A release whose tag does not point at `583cb64e5a2e90679ea7dedadfe47d8ea99abd3e` would publish some other tree. Task 2 checks `git rev-parse v1.0.8^{}` equals that commit.
- A draft or prerelease is not the release the spec chose. Task 2 checks `isDraft` and `isPrerelease` are false.
- Notes other than `Fixed module type` would not match the spec. Task 2 checks the release body.
- A green workflow that published a version other than 1.0.8 would leave npm wrong. Task 3 checks `npm view` returns `1.0.8`.
- A failed workflow followed by a local `npm publish` would break the trusted-publisher constraint. Task 3 stops on a non-zero `gh run watch` and does not publish locally.

### Task 1: Confirm the commit that will be published

**Files:**
- Modify: none
- Test: the checks in Steps 1–4

**Interfaces:**
- Consumes: commit `583cb64e5a2e90679ea7dedadfe47d8ea99abd3e` on `origin/master`, `package.json` version `1.0.8`
- Produces: a go or stop decision. Later tasks run only if every check in this task matches.

- [ ] **Step 1: Confirm HEAD and the remote**

Run:

```bash
git rev-parse HEAD
git status -sb
```

Expected: `583cb64e5a2e90679ea7dedadfe47d8ea99abd3e` and `## master...origin/master`. Untracked files under `docs/superpowers/` are allowed. Any other change is a stop.

- [ ] **Step 2: Confirm the version on that commit**

Run:

```bash
git show HEAD:package.json | node -e "let s='';process.stdin.on('data',d=>s+=d);process.stdin.on('end',()=>console.log(JSON.parse(s).version))"
```

Expected: `1.0.8`

- [ ] **Step 3: Confirm npm and GitHub do not already have 1.0.8**

Run:

```bash
npm view @emamid/svelte-data-table version
gh release view v1.0.8 --repo emamid/svelte-data-table
```

Expected: npm prints `1.0.7`. `gh release view` fails because the release does not exist.

- [ ] **Step 4: Stop or continue**

If any expected value differs, stop and report the difference. Do not create a release.

### Task 2: Create release v1.0.8

**Files:**
- Modify: none in the repository
- Test: `gh release view` and `git rev-parse v1.0.8^{}`

**Interfaces:**
- Consumes: the go decision from Task 1
- Produces: GitHub release tag `v1.0.8` pointing at `583cb64e5a2e90679ea7dedadfe47d8ea99abd3e`, body `Fixed module type`, `isDraft` false, `isPrerelease` false

- [ ] **Step 1: Create the release**

Run from the repository:

```bash
gh release create v1.0.8 \
  --target 583cb64e5a2e90679ea7dedadfe47d8ea99abd3e \
  --notes "Fixed module type" \
  --repo emamid/svelte-data-table
```

Do not pass `--draft` or `--prerelease`.

- [ ] **Step 2: Verify the tag, the notes, and that it is a full release**

Run:

```bash
git fetch origin tag v1.0.8
git rev-parse v1.0.8^{}
gh release view v1.0.8 --repo emamid/svelte-data-table --json tagName,isDraft,isPrerelease,body --jq '{tagName,isDraft,isPrerelease,body}'
```

Expected: `git rev-parse` prints `583cb64e5a2e90679ea7dedadfe47d8ea99abd3e`. JSON is `{"tagName":"v1.0.8","isDraft":false,"isPrerelease":false,"body":"Fixed module type"}`.

- [ ] **Step 3: Stop if the release is wrong**

If the tag, body, draft flag, or prerelease flag differs, stop. Do not delete the release unless the user asks. Do not publish another way.

### Task 3: Confirm npm received 1.0.8

**Files:**
- Modify: none
- Test: `gh run watch` and `npm view`

**Interfaces:**
- Consumes: the release from Task 2
- Produces: a successful `Node.js Package` run and npm version `1.0.8`, or a reported failure with no local publish

- [ ] **Step 1: Watch the workflow the release started**

Run:

```bash
gh run list --repo emamid/svelte-data-table --workflow "Node.js Package" --limit 3
```

Take the run whose head SHA is `583cb64e5a2e90679ea7dedadfe47d8ea99abd3e` and whose event is `release`. Then run:

```bash
gh run watch <run-id> --repo emamid/svelte-data-table --exit-status
```

Expected: exit code 0.

- [ ] **Step 2: Confirm the registry**

Run:

```bash
npm view @emamid/svelte-data-table version
```

Expected: `1.0.8`

- [ ] **Step 3: On failure, stop**

If `gh run watch` exits non-zero, or npm does not show `1.0.8`, report the run URL and the npm version. Do not run `npm publish`.
