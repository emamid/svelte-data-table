# Publish 1.0.8

## Intent

Publish `@emamid/svelte-data-table` 1.0.8 to the public npm registry so other projects can install the module-type fix that is already on `master`. npm is still on 1.0.7.

## Goals

- A GitHub release `v1.0.8` on commit `583cb64` (`Fixed module type`), which is `master` and `origin/master`.
- That release runs the existing `Node.js Package` workflow, and `npm publish` succeeds for 1.0.8.

## Non-goals

- No source, dependency, or workflow changes in this release.
- `@types/node`, dependency bumps, and the publish-workflow cleanup wait for a later release.
- Sveld documentation, and any separate docs-generator package, are out of this release.

## Anti-goals

- Publishing a commit other than `583cb64`, or a version other than 1.0.8.
- Publishing from a laptop with an npm token instead of the repository's trusted-publisher workflow.

## Constraints

- `package.json` on that commit already says `1.0.8`.
- `.github/workflows/release-package.yml` publishes when a GitHub release is created. It publishes to `https://registry.npmjs.org` with provenance. The test job does not block publish. That is how 1.0.7 shipped, and this release uses the same path.
- The release is public. npm already hosts this package as a public package.

## Approaches

1. **Create the GitHub release and let the existing workflow publish.** Chosen. It matches the 1.0.7 release, uses the trusted publisher already configured, and does not change the package.
2. **Fix the workflow, install `@types/node`, and bump dependencies, then publish.** Rejected for this release. Those changes are wanted later, and they would delay the install.
3. **Run `npm publish` locally.** Rejected. The repository publishes through GitHub Actions, not a local token.

## Decisions

- Release tag `v1.0.8`, target `583cb64`, not a prerelease, not a draft.
- Release notes are the commit subject: "Fixed module type". The 1.0.7 notes were one line in the same style.
- Do not change files on `master` before the release.

## Left to the builder

- Create the release with `gh`.
- Watch the `Node.js Package` workflow until it finishes, and confirm npm shows 1.0.8.
- Stop if the workflow fails. Do not publish a second way.
